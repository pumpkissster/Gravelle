# Gravelle 0.8.5

## 更新内容

- 新增管理员图片优化，可按单张图片的文件大小、总像素或最长边判断，仅为命中规则的页面生成 WebP 或 JPEG 副本。原图保持不变，各账号与设备共用优化副本。
- 新扫描的作品命中优化规则时，管理员可选择使用原图或加入优化任务。首次待决策的作品暂不公开；扫描完成弹窗、侧边栏和设置入口提醒待处理数量。支持批量选择、暂停、继续、取消与重试，保存规则前可预览影响。
- 优化副本默认保存在数据目录的 `transcoded` 子目录。Docker 可将 `/data/transcoded` 单独映射到其他文件夹或磁盘；不额外挂载时仍保存在原 `/data` 中。提供容量限制、保留磁盘空间和旧副本清理。
- 新增写真库内以图搜图。管理员启用索引后，用户可上传、拖入或粘贴静态 JPG／PNG／WebP，查找自己可访问且未隐藏的作品，点击结果直达匹配页。支持相同图片、缩放重压缩、完整画面截图及轻中度裁剪；无需 GPU 或下载模型。
- 新增共用后台任务调度，图片优化与索引默认按单张图片排队。管理员可在性能设置将并发数设为 1～8；同一作品的优化和图片索引各自仍逐张处理，实际搜索等待时优先于新后台任务。
- 单页阅读新增上下翻页，支持上下点击、滚轮、键盘与触屏滑动，使用纵向过渡。长图适应宽度时先在页内滚动，达到边缘后再翻页；可在写真库、作品及个人阅读偏好中选择。
- 设置首页改为单列，直接展示服务与数据、用户管理，其他设置通过入口进入二级页面；性能设置区分后台任务与加载、列表偏好。以图搜图上传预览改为纵向布局。
- 修复拖动浏览器窗口大小时瀑布流作品封面闪烁的问题，调整布局时保留已经显示的卡片与图片。

## 使用与升级

图片优化与图片索引**默认关闭**，由管理员在「设置 → 图片优化」「设置 → 图片搜索」中分别启用。子账号不能修改规则、处理优化任务或管理索引；搜索结果和图片访问继续受写真库授权与个人显隐控制。

升级前停止服务并备份完整数据目录，沿用原数据和作品路径：

- **Windows**：停止服务并关闭旧启动器，备份整个 `%LOCALAPPDATA%\Gravelle`，使用 `Gravelle-Setup-0.8.5-x64.exe` 覆盖安装。便携版解压完整的 `Gravelle-Windows-0.8.5-x64.zip`，继续使用原数据目录。
- **Docker**：停止容器，备份完整 `DATA_PATH` 和部署配置，将镜像改为 `pumpkissster/gravelle:0.8.5`，再拉取并启动。保留原项目名称、作品与数据挂载及运行用户。若将 `/data/transcoded` 单独映射，还需同时保存该目录；切换位置前先复制并校验已有副本，挂载本身不会迁移文件。

旧图片搜索索引升级后会在后台逐页补充局部特征，无需手动重建；补充期间已收录页面仍可使用原有整图搜索，完成后的页面才支持截图／裁剪匹配。首次索引和大图处理会消耗 CPU、内存与磁盘 I/O，默认并发 1，可暂停任务。

需要回退时，恢复升级前的完整资料备份并使用对应旧程序或镜像。不要让两个服务同时使用同一数据目录，也不要直接用旧程序打开升级后的数据库。详细说明见[图片优化](../transcoding.md)、[以图搜图](../image-search.md)、[性能设置](../performance.md)和[Docker 独立优化目录](../docker-release.md#图片优化目录单独映射)。

## 当前限制

- 提供 Windows x64 安装包／便携包和 Linux amd64／arm64 Docker 镜像。安装程序尚未做代码签名，Windows 可能提示“未知发布者”；从本项目发行页下载并核对 SHA-256 校验值。
- 图片优化不预测输出空间，当前显示的是已生成优化副本的实际占用；仅命中页会生成副本，不代表整部作品的全部文件大小。单页源文件读取上限为 64 MiB，动画图片暂不优化。
- 以图搜图仅查找自己的写真库。查询图片不超过 64 MiB、1 亿像素，只支持静态 JPG／PNG／WebP；不提供人物识别、语义搜索或全网查图。完整截图及轻中度裁剪通过局部特征与几何验证，微小裁片、严重模糊、低纹理、重复图案、大面积遮挡或拼图可能找不到。
- 后台并发数不是 CPU 百分比或服务总内存上限，调高后资源占用会叠加。受限图片处理进程仍可能因内存不足、图片损坏或超时失败。
- 已完成本地合成样本与独立运行验证；实际照片的匹配效果、超大写真库、群晖 NAS 的资源占用及手机触屏体验仍取决于设备和素材，尚未完成对应实机验收。
