# 图片优化

0.8.5 提供按规则逐图优化。管理员在「设置 → 图片优化」操作，子账号只能按管理员的选择阅读。

设置首页采用单列，直接展示「服务与数据」「用户管理」；界面、性能、阅读和优化通过下方的单列入口进入二级页面。

## 开始使用

1. 打开「优化规则」，设置触发条件与输出参数。功能默认关闭；启用后按源文件重新判断已有作品，新扫描的作品也使用同一规则。
2. 点击「预览并保存规则」，查看新增命中、不再命中和需要重新优化的图片。保存规则不会自动开始优化。
3. 在「作品与任务」筛选、多选作品，选择「使用原图」或「优化」。首次命中且尚未选择的作品暂不显示在普通写真库中，可在管理页预览。
4. 使用原图后作品立即显示，仍命中规则时继续保留在管理名单中。选择优化只处理命中的图片，其余页继续读取原图；全部命中页成功后才展示新作品。

导入或扫描完成后，发现新增待决策作品时，会提示是否前往图片优化页面。选择稍后处理后，侧边栏个人信息上方继续显示提醒，设置中的「图片优化」入口右侧也显示数量。数量包含首次待选择和规则变更后等待再次确认的作品；已选择原图、正在执行、暂停、失败或取消的任务不混入待决策数量。登录时已有的待决策记录只显示持续提醒，普通重复扫描不反复弹窗。

可以暂停、继续、取消或重试任务。部分成功的作品不会被当作完成；重试复用仍有效的成功页。任务和选择保存在服务端，重启后恢复；关闭管理页面不会停止后台任务。源文件不被修改。

图片优化与图片索引默认共用一个图片处理名额，按单张图片排队执行。管理员可在「设置 → 性能设置」将后台任务并发数设置为 1～8，提高后允许不同作品并行优化，或与图片索引同时进行；同一作品内部仍逐页处理，降低数值不会中断正在执行的任务。该设置对整个服务生效，重启后保留，详见 [性能设置](performance.md)。

## 默认规则

| 配置 | 默认值 |
| --- | --- |
| 图片优化开关 | 关闭 |
| 源文件大小超过 | 10 MiB |
| 总像素超过 | 4000 万像素 |
| 最长边超过 | 10000 px |
| 输出格式、质量 | WebP、88 |
| 输出最长边 | 3840 px |
| 每本作品内部并发 | 1 张图片 |
| 服务端后台任务并发数 | 1（可设 1～8） |
| 单任务内存、超时 | 1024 MiB、120 秒 |
| 优化图片容量上限 | 10240 MiB |
| 保留磁盘空间 | 512 MiB |

任一触发条件命中即可。触发条件输入 0 表示关闭该条件，启用优化时至少保留一项；容量上限输入 0 表示不限。MiB 按 1024 × 1024 字节计算。输入文件大小判断逐页进行，ZIP／CBZ 使用内部图片大小，不能用整包大小代替。

## 修改规则与空间管理

修改输入阈值不会使同一输出参数的有效图片失效；修改格式、质量或最大尺寸会列出需要重做的页。已展示的作品在替换完成前保留仍对应当前源文件的旧有效副本，整批所需图片成功后统一切换。源文件发生变化时不会把旧内容当作新图返回，需要重新扫描和处理。

管理页显示实际优化图张数、占用和服务端目录。只统计已发布的优化副本，不代表整部作品总大小；「已存储优化图」另包含未发布和旧版本。默认位于资料目录的 `transcoded/<作品ID>/`；Docker 中为 `/data/transcoded/<作品ID>/`，对应宿主机的 `DATA_PATH/transcoded`。账号与设备共用副本，访问仍检查当前账号的写真库权限。

Docker 可选用 [compose.optimization.yaml](../compose.optimization.yaml) 将同一个容器路径 `/data/transcoded` 单独映射到宿主机的其他文件夹或磁盘，数据库与账号资料继续使用原 `/data`。不单独映射时，副本正常存放在 `DATA_PATH/transcoded`；无需额外硬盘，也没有必须拆分目录的性能要求。只填写 `OPTIMIZED_PATH` 不会改变位置，还需同时加载覆盖配置或在容器管理器中添加挂载。已有副本不会自动迁移；切换前需停服务、复制并校验完整内容。配置命令与迁移步骤见 [Docker 图片优化目录](docker-release.md#图片优化目录单独映射)。

「清理旧副本」只清理不再被当前或待发布映射使用的已登记图片。当前有效图片不会自动回收，达到容量或剩余空间限制时暂停任务。服务启动时检查自身严格命名的异常退出暂存文件与未登记输出，保留数据库引用、陌生文件和链接目录。这项容量管理仅统计优化图片副本，不包括封面。

## 当前限制

- 单页源文件读取上限为 64 MiB；动画图片暂不优化，可选择原图。超过读取上限的原图也受现有阅读限制。
- 输出支持 WebP、JPEG，质量范围 1～95，最长边范围 512～8192 px。带有效色彩配置的图片转换至 sRGB，保留透明度与旋转方向；JPEG 的透明背景使用白色。
- 单任务内存范围 256～8192 MiB，超时范围 10～600 秒。内存不足、超时或损坏图片会明确失败，不以原图静默替代已选优化的图片。
- 本地合成测试中，一张 9903 × 6959、约 51.2 MiB 的 JPEG 生成约 4.7 MiB 的 3840 × 2699 WebP；这不能预测其他照片的大小或耗时。用户提到的 47.6MB 原图和真实 NAS 的速度、内存峰值与画质仍需实测。没有空间占用预测功能。
