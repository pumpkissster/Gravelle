# 网络设置

管理员在“设置 → 网络设置”管理 HTTPS 连接、安全入口、独立分享服务和公网分享地址。子账号与分享访客不能读取或修改这些设置。

## HTTPS

“启用 HTTPS”默认关闭。关闭时，Gravelle 沿用现有 HTTP 端口，无需配置证书。通过反向代理提供公网 HTTPS 时，也保持此开关关闭，在代理中配置证书，并在公网分享地址填写实际的 HTTPS 地址。

需要由 Gravelle 自己提供 HTTPS 时，打开开关，点击“上传证书”选择电脑上的 `.pfx` 或 `.p12` 文件，并填写可选的证书密码。点击“保存网络设置”后才会上传、验证并启用；选择后也可以取消上传。文件最大 16 MiB。

上传的证书保存在资料目录的 `https-certificates` 文件夹内，Docker 使用 `/data/https-certificates`，无需额外挂载证书目录。也可以沿用路径方式，填写运行服务的设备可读取的证书绝对路径。页面会显示实际的 HTTPS 端口和监听状态。

证书文件需包含服务器证书和对应的私钥。密码留空表示保留已保存密码；如需改用无密码证书，点击“清除已保存密码”后保存。页面只显示密码是否已设置，不会回显已有密码。

保存前会检查证书、密码、有效期和监听端口。配置失败会显示原因并保留原设置。更换磁盘上的证书后，需要重新保存网络设置或重启服务以载入新文件。此功能使用已有证书；申请或续期证书由管理员自行处理。访问地址应与证书签发的域名或 IP 相符，导入文件不会改变浏览器的证书信任设置。

- Windows／macOS：停止服务后，在启动器设置 HTTPS 端口，默认 `8443`。启动器仍从本机 HTTP 打开管理页面，HTTPS 端口用于使用证书访问。
- Docker：主 HTTPS 容器端口固定为 `8443`，在部署时映射，网页不能修改。直接上传时保留原 `/data` 挂载即可；使用已有服务器文件时，可将证书目录只读映射到 `/certificates`，网页填写容器内的路径。

Docker 证书模式示例（保留原媒体和资料挂载）：

```yaml
ports:
  - "8080:8080"   # 原 HTTP 管理与健康检查
  - "8443:8443"   # 主 HTTPS
  - "8081:8081"   # 可选独立分享；证书模式下使用 HTTPS
volumes:
  - "/path/to/certificates:/certificates:ro"
```

已有 HTTP 管理端口继续可用，证书配置出错时可从原管理地址修正。开启独立分享后，启用 HTTPS 会让原分享端口改为 HTTPS，与完整阅读器共用证书，但继续只提供分享页面和访客接口；改变 HTTPS 开关后需核对公网分享地址的协议及代理后端协议。

保存的证书密码在服务端加密，恢复资料时应保留完整资料目录，包括 `https-password.key` 与上传证书所在的 `https-certificates`。使用外部文件路径时，另行保留该证书文件。不要将证书私钥、证书密码或该密钥提交到公开仓库。

## 安全入口

启用后设置 8～64 位入口码，可使用英文字母、数字、下划线与短横线。例如入口码为随机生成的一串字符，完整入口地址是 `http://服务器IP:端口/入口码`。请保存完整地址，并使用与账号密码不同的随机入口码。

未通过安全入口的浏览器无法打开完整阅读器、登录接口或管理接口。进入正确入口后，浏览器取得独立的入口凭据，再继续正常账号登录；入口凭据不会授予账号权限。已有有效入口凭据的浏览器可以继续访问同站点页面，因此不能用该浏览器访问根地址的结果判断匿名访问是否被拦截，请使用无痕窗口验证。

修改入口码后，旧入口及旧入口凭据失效；当前保存设置的浏览器获得新入口凭据。分享阅读使用独立的分享密码和会话，不要求访客知道安全入口码。

### 忘记入口时恢复

只能在运行服务的设备本机恢复，不提供公网恢复接口：

- Windows／macOS：启动器中的“关闭安全入口”会先停止它自己启动的阅读器，再备份资料并关闭安全入口。完成后可重新启动，从普通地址进入并重新设置。
- Docker：先停止容器，再通过同一部署配置运行离线维护命令。该命令使用原资料挂载和运行用户，不启动阅读器、扫描媒体或重置账号密码。

以默认 Compose 服务 `gravelle` 为例：

```sh
docker compose stop gravelle
docker compose run --rm --no-deps gravelle python server.py --reset-security-entry --data /data
docker compose up -d gravelle
```

如果你自行修改过 Compose 服务名，请在上述命令中使用实际服务名。恢复前保存部署配置与完整资料备份；不要手工删除数据库、密钥或资料目录锁文件，也不要同时启动两个服务打开同一资料目录。

## 独立分享端口

默认关闭：分享页面与完整阅读器使用同一个端口。开启后：分享页面、密码验证和图片请求只由独立分享端口提供，完整阅读器端口拒绝访客分享请求。

独立分享端口只允许分享页面、对应分享接口和必需的页面资源；根地址、账号登录、用户／写真库管理、普通作品接口均不可使用。只有入口隔离生效，不会因此授予访客其他作品或管理员权限。关闭／到期的分享仍由服务端逐次拒绝读取，已经收到的图片和截图不能收回。

- Windows／macOS：在启动器中设置分享端口，停止服务后再修改。网页仅控制开关，不编辑端口；局域网访问仍受启动器的局域网开关控制。
- Docker：容器内分享端口固定为 `8081`，网页不能修改。宿主机端口可以通过部署映射选择，映射本身不会自动开启独立分享服务。启用 HTTPS 时，该端口提供 HTTPS；关闭 HTTPS 时提供内部 HTTP。

Docker 映射示例：

```yaml
ports:
  - "8080:8080"   # 完整阅读器：仅在内网使用
  - "8081:8081"   # 独立分享：在网页开启后才提供服务
```

修改映射后重新创建容器。若端口被占用，开启会失败并保留原设置；根据页面提示调整启动器端口或 Docker 宿主机映射。

## 公网分享地址

填写访客实际使用的地址，例如 `https://photos.example.com`。只填写协议、域名或 IP 与可选端口，不附加 `/share/…`、安全入口码、账号密码、查询参数或片段。

创建或复制分享链接时，将该地址与作品的随机分享路径组合。配置地址不会自动建立内网穿透、申请证书或检查公网连通性，也不会向该地址发出后台请求。

未填写时使用当前访问地址推导链接；反向代理、Docker 端口映射或不同的公网端口可能使推导结果无法从外网使用，建议管理员明确填写实际公网地址。

## 反向代理与内网穿透

公网链路最终应只连接独立分享端口，完整阅读器端口保留内网访问；不要保留其他可绕过隔离、直达完整端口的公网映射。可通过反向代理配置 HTTPS 和证书，并按需使用内网穿透，无需改变分享路径。

例如内网完整阅读器使用 `http://服务器IP:8080`，独立分享使用 `http://服务器IP:8081`，公网地址使用 `https://photos.example.com`。将公网转发的后端改为独立分享端口后，访客从公网根地址找不到登录页面。仅仅更换域名、端口或隐藏按钮不等于完成隔离。

配置代理时保留实际访问的 Host，并正确设置 `X-Forwarded-Proto`；HTTPS 访客会话需要正确的协议头。不要把任意客户端提供的代理头当成可信身份。软件的密码尝试限制仍有边界，入口隔离与 HTTPS 不能替代强密码和正常的访问管理。
