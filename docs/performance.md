# 性能设置

管理员打开「设置 → 性能设置」，可以分别设置后台任务并发数和自动扫描间隔；同页的加载、缓存和列表选项按当前账号保存在当前浏览器。「后台任务」「自动扫描」和「加载与列表」分别显示。

## 后台任务

「后台任务并发数」默认 **1**，允许设置 **1～8**。默认优先完成当前正在优化的作品，再处理下一本；提高并发后，可以让多本作品同时优化，也可以让优化与图片索引同时进行。每本作品内部始终逐张处理，图片索引自身也仍逐张建立，不会因调高设置同时启动多路索引。

每张图片处理完成后仍会释放共用名额，索引和实际搜索可以在页与页之间穿插，不必等整部作品完成。按作品优先是图片优化队列的处理顺序，不会让一本作品一直独占处理名额。设为 1 时不会同时执行多个图片处理任务，也不会自动提高并发。

实际图片搜索的解码也遵守共用名额，等待时优先于新的后台处理；不会强制中断已经开始的图片。降低同时任务数不会终止正在执行的任务，新任务会等待已有任务释放名额。设置保存在服务端，重启后保留，子账号不能修改。

后台优化与索引解码使用较低运行优先级，实际搜索保持正常优先级。共用名额用于限制图片处理并行，不是 CPU 百分比或整个服务的内存上限；即使并发 1，大图处理也可能使一个核心持续繁忙。搜图单个解码进程仍有 1024 MiB／60 秒限制，优化单个进程使用自己的内存和超时规则。提高并发后，资源占用可能叠加。

Windows 使用 Job Object、Linux 使用进程资源限制。macOS 版每 0.1 秒检查图片工作进程的峰值常驻内存，超出预算即结束该进程；采样保护可能短暂超过预算，不是操作系统的硬性分配上限。各平台均保留图片像素预检和服务端超时控制。

图片优化与索引在空闲时等待任务通知，并保留低频兜底检查；新任务或并发设置变化会唤醒处理。目录数据未变化时，网页只核对轻量状态，继续使用已有列表。图片搜索和图片优化页面在浏览器标签隐藏时暂停状态查询，重新显示后立即刷新。

## 自动扫描

管理员可设置自动扫描写真库的间隔，单位为秒，允许 **0～604800**（最长7天）。**0 关闭定时扫描，保存后生效**；关闭后仍可手动扫描写真库。

此设置保存在服务端，重启后保留，子账号不能修改。尚未设置过时沿用部署时的扫描间隔，通常为300秒。它独立于图片处理并发数，也不会保存在浏览器的个人偏好中。

## 当前设备

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 条漫加载步进 | 3 | 预加载当前页前后各 3 页。 |
| 封面加载并发数 | 3 | 同时加载最多 3 张列表封面。 |
| 图片缓存数量限制 | 0 | 不按数量限制阅读器的图片缓存；设置正整数时优先释放较早使用、当前未显示的图片。 |
| 图片解码缓存预算（MiB） | 256 | 按图片宽×高×4 字节估算内存，限制附近预加载页和未显示的阅读图片；0 表示不按内存限制。 |
| 作品页面容量 | 0 | 使用瀑布流滚动加载；设置正整数时按指定数量分页。 |

图片缓存数量限制不控制服务端的优化副本、图片搜索索引或浏览器自身的网络缓存，也不代表会立即预加载整个写真库。当前写真按单本浏览，无需显示章节页面容量；旧版本的章节偏好继续兼容保存。

数量和解码预算同时生效。正在显示的单页、双页和连续滚动可见页会保留，所以它们本身超过预算时不会被清空。预加载先估算，加载完成后按实际图片尺寸修正；这是应用图片缓存的估算预算，不是浏览器进程的硬性内存上限。服务端的封面与优化图空间管理见[缓存管理](cache.md)。

瀑布流只保留视口附近的作品卡片，滚回原处时再显示对应卡片。列表仍保留滚动位置和已选作品。连续阅读按正在加载与保留的图片统计缓存，分页容量和解码预算的设置方式不变。

## 服务端读图

近期读取过的目录、ZIP／CBZ 页面可复用已校验的临时磁盘快照。再次访问时仍检查权限和源文件版本；如果文件系统无法可靠确认版本，或快照空间不足，服务端会直接分块读取源文件。快照最多占用 256 MiB、保留 64 项，随服务结束释放。

加密分享使用临时密文文件分块发送，避免在服务端内存中同时保留整张原图和完整加密包。访问校验在发送前及发送期间继续生效。操作系统仍可能使用文件缓存，浏览器也仍需解密和显示图片。
